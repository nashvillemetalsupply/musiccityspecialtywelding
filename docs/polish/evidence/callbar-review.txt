Root cause
The active shared-bar overrides in app/globals.css:2561-2562 use --sw-neon, --sw-fire, and --sw-chalk. Those variables are declared only on .ms-site at app/globals.css:1794-1810.

The home page wraps MobileQuickActions inside its .ms-site root, so the variables resolve and the bar is orange/bone. Privacy and Terms put .ms-site only on the main element, then render MobileQuickActions as a later sibling at app/privacy/page.tsx:238 and app/terms/page.tsx:183. The bar cannot inherit the scoped variables.

A custom property that is missing when var() is resolved invalidates the whole declaration at computed-value time. Therefore:
- the later first-child gradient invalidates instead of falling back to the earlier orange background;
- the later Quote color invalidates and inherits the page's near-black body color.

Exact one-file fix
File: app/globals.css
Replace the two rules at lines 2561-2562 with:

.ms-mobile-cta a:first-child { background: linear-gradient(180deg, var(--sw-neon, #ffb46b), var(--sw-fire, #ff8a2a) 60%); color: #1b0f02; }
.ms-mobile-cta a:last-child { background: #241d12; color: var(--sw-chalk, #f3ead8); border-left-color: #000; }

Why this is the minimal shared fix
- It changes one file and only the shared mobile CTA declarations.
- On the home page, inherited --sw-* values still win, so its current appearance is unchanged.
- Outside .ms-site, the fallbacks equal the current Shop Wall token values declared in the same stylesheet.
- No markup, copy, navigation, visibility logic, breakpoints, tracking, headers, CSP, or environment behavior changes.
- Fixing the shared component's declarations covers Privacy, Terms, the not-found route, and any future placement outside .ms-site.
