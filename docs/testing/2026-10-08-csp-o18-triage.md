## Evidence for the non-allowlisted verdicts

- Grep of `app`, `lib`, `components` for `WebAssembly`, `wasm`, `apis.google`, `gapi`, `eval(`, `new Function`: only hit is `lib/csp-report.ts`, which merely names `eval` / `wasm-eval` as report keywords.
- `npm run build`, then search of `.next/static`: no `WebAssembly` / `.wasm`, no `WebAssembly.instantiate|compile`, no `new Function(`, no `eval(` call, no `apis.google.com`. Nothing the site ships uses WebAssembly, eval, or gapi, including the /board bundle.
- Therefore `'wasm-unsafe-eval'` is NOT added, and `'unsafe-eval'` must never be added (the policy test fails if it appears). The `wasm-eval`, `eval`, gapi and toolytics reports come from browser extensions on the visitors' machines.
- Caveat: the `/board` wasm reports include source "unknown", which is consistent with extension injection. If they persist after the flip window with no extension explanation, re-open this.
